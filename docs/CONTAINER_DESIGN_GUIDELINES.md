# 容器設計準則

## 1. 文件目的

本文件定義播放器頁面中，主要內容容器的盒模型、分隔方式與內容貼齊規則。

本文件聚焦於：

- 容器的外圍留白
- 容器之間的起始線一致性
- 容器內部內容的貼齊方式
- 容器層級的責任分工

本文件不描述具體功能流程，也不描述特定元件名稱。

## 2. 適用範圍

本規範適用於同一頁面層級、彼此並列或堆疊的主要內容容器。

判斷原則如下：

- 該容器直接承接 page-level 內容排列
- 該容器是視覺分區的主要邊界
- 該容器的顯示或隱藏會影響整段內容，而非單一小元件

## 3. 容器盒模型契約

所有適用本規範的主要內容容器，應共享相同的外圍留白設定：

- 左側外距：`16px`
- 上側內距：`12px`
- 右側內距：`16px`
- 下側外距與內距：`0`

此契約的核心目的如下：

- 建立一致的左側基準線
- 建立一致的上方起始距離
- 讓主要內容容器形成同一組版面節奏

## 4. 容器對齊原則

同層主要內容容器必須遵守下列對齊原則：

- 左側起始線一致
- 上方起始線一致
- 不允許單一容器額外向內縮排
- 不允許容器自行破壞 page-level 的整體節奏

在視覺上，所有 page-level 容器都應被視為同一組版面系統中的兄弟節點。

## 5. 容器內部內容貼齊原則

容器內部的直接子項目，應遵守以下規則：

- 從容器上方開始排列
- 預設寬度應撐滿容器可用寬度
- 不應額外引入無必要的左右縮排
- 不應依賴額外包裝層來製造與容器邊界之間的留白

若需要垂直節奏，應使用明確且可控的垂直間距，而不是透過多層 wrapper 疊加產生。

若容器內部承載的是清單型列項目，應額外遵守以下貼齊原則：

- 列項目的主要視覺錨點必須直接貼齊容器內容基線
- 橫向留白應由欄位之間的 gap 提供，不應透過列項目自身的左側內距把內容再往內推
- 以縮圖為主視覺錨點的清單，縮圖左緣就是該列的起始線
- 此原則適用於播放器頁中的同類影片清單，例如「接下來推薦」與「播放清單」；後續新增同型清單時，預設沿用同一套起始線與間距語言

## 6. 容器責任歸屬

容器層級的責任應明確分層：

- page-level 容器：負責主要區塊之間的分隔與外圍留白
- 容器內部元件：負責自身內容排列，但不應重新定義 page-level 的起始線

若同一份留白同時由父層與子層重複定義，容易造成：

- 起始線不一致
- 實際間距難以預測
- 後續調整時必須同時修改多個層級

## 7. 容器精簡原則

應保留的容器：

- 有明確的版面責任
- 是主要視覺分區的邊界
- 是整段內容顯示或隱藏的邊界

應移除的容器：

- 只用來再包一層，沒有新增版面責任
- spacing 可以直接由父層或實際內容節點承接
- 拿掉後不影響版面理解、功能切分與維護邏輯

## 8. 不建議的模式

以下模式應視為反模式：

- 父容器已提供 page-level 留白，子容器再重複加入同類型留白
- 為了拉出間距而新增沒有責任的包裝層
- 同層容器採用不同的左側基準線
- 內容不是從容器頂部開始，而是各自再往下偏移

這些模式會直接降低版面一致性，並提高維護成本。

## 9. 調整前檢查項目

在修改本規範或套用到新頁面前，應先確認：

- 這次調整影響的是 page-level 容器，而不是單一元件內部樣式
- 修改後，同層容器的左側與上方基準線仍然一致
- 內容是否仍然維持「由上而下、滿寬起始」的排列方式
- 是否引入了新的冗餘 wrapper
- 是否把 page-level spacing 錯放到子元件內部

若上述條件無法成立，應重新界定責任層級，而不是直接修改 spacing 數值。

# 系列播放清單規格驗證測試 (Spec. Test)

## 文件狀態

- 狀態：`User Story v1` baseline
- 版本：`v1`
- 性質：系列播放清單主題的 QA 測試基線
- 對應文件：
  - [`PLAYER_SRS.md`](./PLAYER_SRS.md)

## 1. 文件目的

本文件定義「系列資料夾 CID + root `playlist.json`」主題的 QA 驗證基線，作為後續 `Developer` 開發、自測與驗收討論的最低考卷。

本版文件分為三層：

- `Spec. Test`：最低送測門檻與主要 Happy Path
- `Scenario Test`：常見產品流程與模式切換情境
- `Edge Test`：錯誤資料、歧義輸入與狀態邊界

本版不涵蓋：

- 季別巢狀結構
- 多個播放清單檔案
- 掃描資料夾自動生成集數
- 系列內容動態更新策略
- 單一系列 CID 底下承載多個 show 或 library

## 2. 對應 User Story

1. 系統必須同時支援「單一影片 CID 直接播放」與「系列資料夾 CID + root `playlist.json` 播放清單」兩種模式。
2. 當輸入 CID 根目錄存在格式正確的 `playlist.json` 時，系統應將該 CID 視為系列內容入口，優先顯示播放清單。
3. 當輸入 CID 不存在有效的 `playlist.json`，但存在可播放的單片影片入口時，系統應維持目前的單片 CID 直接播放行為。
4. 系列模式下，介面應顯示完整且有順序的集數清單，並清楚標示目前選取的集數。
5. 系列模式下，系統應預設選取第一個可播放集數，並在主要播放器中載入該集的待播畫面與封面縮圖，但不得自動開始播放。
6. 預設載入第一個可播放集數的待播畫面時，系統不得立即寫入觀看歷史，且不得將該集視為已開始播放。
7. 播放清單中的集數順序、標題與可播放狀態，必須以 `playlist.json` 為唯一依據，不得透過掃描資料夾名稱自動推斷。
8. 播放清單中的每一集至少必須顯示集數編號與標題。
9. 當使用者點選某一集時，系統應載入同一個系列根目錄下、由 `playlist.json` 指定路徑的該集播放內容。
10. 當 `playlist.json` 缺失、格式錯誤，或其中沒有任何可播放集數時，系統不得自動改播其他集數，並應顯示明確錯誤訊息；若該 CID 同時符合單片模式，則應依既定判斷規則決定是否回退為單片播放。
11. 系統的狀態模型必須能區分「系列根 CID」與「目前選取的集數」，避免後續分享連結、觀看歷史與續播功能產生歧義。

## 3. 規格解讀基線

為避免實作歧義，本版測試固定採用以下解讀：

- 系列模式的權威來源只有 root `playlist.json`。
- 系統不得透過掃描 `ep01/`、`ep02/` 等資料夾名稱來補齊或修正播放清單。
- 若同一個 CID 同時存在有效 `playlist.json` 與單片播放入口，本版測試固定採用 `playlist.json` 優先，視為系列入口。
- 系列模式中的「預設載入第一個可播放集數」只代表待播狀態，不代表已經播放。
- 待播狀態至少要能看出目前主播放器已對應到哪一集，且封面縮圖已載入或準備載入。
- 觀看歷史、續播與分享的最小識別模型，必須至少能區分「系列根 CID」與「集數路徑或集數識別」。
- `playlist.json` 中若某集標記為不可播放，系統可顯示該集，但不得將其當成預設待播集數。

## 4. 測試前置條件

### 4.1 測試資產

至少準備以下測試資料：

- `CID-SINGLE-OK`
  - 單片模式資料夾
  - root 含 `index.m3u8`
  - 不含 `playlist.json`
- `CID-SERIES-OK`
  - 系列模式資料夾
  - root 含有效 `playlist.json`
  - 至少包含 `ep01/`、`ep02/`、`ep03/`
  - `ep01` 與 `ep02` 可播放
- `CID-SERIES-FIRST-UNPLAYABLE`
  - 系列模式資料夾
  - `playlist.json` 中第一集 `playable=false`
  - 第二集為第一個可播放集數
- `CID-SERIES-EMPTY`
  - root 含有效 `playlist.json`
  - `episodes` 為空陣列，或全部 `playable=false`
- `CID-SERIES-BROKEN-PLAYLIST`
  - root 含 `playlist.json`
  - JSON 格式錯誤或必要欄位缺失
- `CID-BOTH-SERIES-AND-SINGLE`
  - 同一 CID 同時存在有效 `playlist.json` 與單片 `index.m3u8`

### 4.2 `playlist.json` 最小契約

本版測試以以下最小契約作為基線：

```json
{
  "version": 1,
  "title": "Series Title",
  "episodes": [
    {
      "id": "ep01",
      "number": 1,
      "title": "Episode 1",
      "path": "ep01/",
      "playable": true
    }
  ]
}
```

### 4.3 測試環境前置

- 測試系列模式的首次載入前，需清除與觀看歷史、續播、分享相關的本機儲存資料。
- 若要驗證「不應寫入觀看歷史」，需能觀察或檢查對應的本機歷史資料變化。
- 若要驗證「不得自動播放」，需能觀察播放器停留於待播狀態，而非進入播放中狀態。

## 6. Spec. Test

### Spec-PL-001 單片模式與系列模式的基本分流

**目的**

驗證系統能依輸入 CID 的內容，在單片模式與系列模式之間做出正確分流。

**前置條件**

- 準備 `CID-SINGLE-OK`
- 準備 `CID-SERIES-OK`

**步驟**

1. 輸入 `CID-SINGLE-OK`。
2. 觀察頁面是否直接進入單片播放流程。
3. 再輸入 `CID-SERIES-OK`。
4. 觀察頁面是否先進入系列播放清單流程。

**預期結果**

1. `CID-SINGLE-OK` 走單片模式，維持目前直接播放單片的既有行為。
2. `CID-SERIES-OK` 走系列模式，顯示播放清單，而不是直接播放任意一集。
3. 兩種模式的入口判斷不互相混淆。

### Spec-PL-002 `playlist.json` 優先判斷

**目的**

驗證當同一個 CID 同時具備有效 `playlist.json` 與單片入口時，系統依基線採用系列模式優先。

**前置條件**

- 準備 `CID-BOTH-SERIES-AND-SINGLE`

**步驟**

1. 輸入 `CID-BOTH-SERIES-AND-SINGLE`。
2. 觀察系統初始模式。

**預期結果**

1. 系統將該 CID 視為系列入口。
2. 介面優先顯示播放清單。
3. 系統不直接進入單片自動播放流程。

### Spec-PL-003 系列播放清單呈現

**目的**

驗證系列模式下，播放清單內容完全以 `playlist.json` 為依據，並正確顯示集數與標題。

**前置條件**

- 準備 `CID-SERIES-OK`

**步驟**

1. 輸入 `CID-SERIES-OK`。
2. 觀察右側或指定區域的集數清單。
3. 比對清單順序與 `playlist.json` 的 `episodes` 順序。
4. 檢查每一列的基本資訊。

**預期結果**

1. 清單完整顯示 `playlist.json` 中所有需顯示的集數項目。
2. 每一集至少顯示集數編號與標題。
3. 顯示順序與 `playlist.json` 一致。
4. 系統不依資料夾名稱自行重排或補集數。
5. 在目前裝置寬度下，每一列都以縮圖左緣作為一致的視覺起始線，且縮圖與文字之間維持一致的欄位間距。

### Spec-PL-004 預設待播集數與歷史保護

**目的**

驗證系列模式初次載入時，系統會預設選取第一個可播放集數並載入待播畫面，但不自動播放，也不污染觀看歷史。

**前置條件**

- 清除觀看歷史與續播相關本機資料
- 準備 `CID-SERIES-OK`

**步驟**

1. 輸入 `CID-SERIES-OK`。
2. 觀察目前被選取的集數。
3. 觀察主要播放器狀態。
4. 檢查觀看歷史是否新增紀錄。

**預期結果**

1. 系統預設選取第一個可播放集數。
2. 主要播放器已對應到該集內容，並顯示待播畫面或封面縮圖。
3. 系統不會自動開始播放。
4. 系統不會立即寫入觀看歷史。
5. 系統不會將該集標記為已開始播放。

### Spec-PL-005 手動切換集數並載入對應內容

**目的**

驗證使用者手動選擇其他集數時，系統會載入 `playlist.json` 指定的對應路徑內容。

**前置條件**

- 準備 `CID-SERIES-OK`

**步驟**

1. 輸入 `CID-SERIES-OK`。
2. 等待預設待播畫面完成初始化。
3. 點選 `ep02`。
4. 觀察目前選取集數與播放器內容。

**預期結果**

1. `ep02` 成為目前被選取的集數。
2. 播放器切換到 `playlist.json` 指定的 `ep02` 路徑內容。
3. 清單中的選取狀態同步更新。
4. 切換集數後，系統仍維持「未按播放前不自動播放」的產品規則，除非另有明確規格。

### Spec-PL-006 無有效可播放集數時的錯誤處理

**目的**

驗證 `playlist.json` 雖存在，但沒有任何可播放集數時，系統不會擅自回退或自動改播。

**前置條件**

- 準備 `CID-SERIES-EMPTY`

**步驟**

1. 輸入 `CID-SERIES-EMPTY`。
2. 觀察頁面回饋與播放器狀態。

**預期結果**

1. 系統顯示清楚的錯誤訊息或空清單提示。
2. 系統不會自動選取任何不可播放集數。
3. 系統不會自動改播其他集數。
4. 系統不會直接進入播放中狀態。

### Spec-PL-007 第一集不可播放時的預設選取

**目的**

驗證當播放清單中的第一集不可播放時，系統會改選第一個可播放集數作為待播目標。

**前置條件**

- 準備 `CID-SERIES-FIRST-UNPLAYABLE`

**步驟**

1. 輸入 `CID-SERIES-FIRST-UNPLAYABLE`。
2. 觀察系統預設選取的集數。

**預期結果**

1. 系統不會選取 `playable=false` 的第一集作為待播目標。
2. 系統會選取清單中第一個 `playable=true` 的集數。
3. 主要播放器載入該集的待播畫面，不自動播放。

## 7. Scenario Test

### Scenario-PL-001 使用者在單片與系列內容之間連續切換

**目的**

驗證使用者在同一工作階段中先看單片、再看系列，或反向切換時，頁面狀態不互相污染。

**步驟**

1. 先輸入 `CID-SINGLE-OK` 並完成單片載入。
2. 再輸入 `CID-SERIES-OK`。
3. 再返回輸入 `CID-SINGLE-OK`。

**預期結果**

1. 單片模式與系列模式之間可穩定切換。
2. 系列清單、目前選取集數與單片播放狀態不會互相殘留。
3. 回到單片模式後，不會誤顯示系列播放清單。

### Scenario-PL-002 系列模式內跨集數切換

**目的**

驗證使用者在系列模式下連續切換多個集數時，主播放器、選取狀態與待播畫面能保持一致。

**步驟**

1. 輸入 `CID-SERIES-OK`。
2. 依序點選 `ep02`、`ep03`、`ep01`。
3. 每次切換後都觀察播放器與清單狀態。

**預期結果**

1. 每次點選後，都只會有一個目前選取集數。
2. 播放器內容與目前選取集數一致。
3. 集數切換不會出現前一集封面、下一集標題等混搭狀態。

### Scenario-PL-003 系列識別與後續功能可追蹤性

**目的**

驗證系列模式具備可追蹤的識別模型，後續可安全接續分享、觀看歷史與續播功能。

**步驟**

1. 輸入 `CID-SERIES-OK`。
2. 點選 `ep02` 並使其成為目前待播集數。
3. 檢查系統內部或可觀察狀態是否能同時辨識系列根 CID 與目前集數。

**預期結果**

1. 系統不只記住一個通用 CID。
2. 系統可區分「系列入口」與「目前集數」。
3. 後續若接上分享、觀看歷史與續播，不會因識別不足而混淆不同集數。

## 8. Edge Test

### Edge-PL-001 `playlist.json` 格式錯誤

**目的**

驗證 `playlist.json` 為破損 JSON 或無法解析時，系統能安全失敗。

**前置條件**

- 準備 `CID-SERIES-BROKEN-PLAYLIST`

**步驟**

1. 輸入 `CID-SERIES-BROKEN-PLAYLIST`。
2. 觀察頁面與播放器狀態。

**預期結果**

1. 系統不會崩潰。
2. 系統顯示清楚的錯誤訊息。
3. 系統不會自動改播任意一集。

### Edge-PL-002 `playlist.json` 缺少必要欄位

**目的**

驗證 `playlist.json` 雖可解析，但缺少最小契約欄位時，系統不會誤判為有效播放清單。

**步驟**

1. 載入一份缺少 `episodes` 或 `path` 等必要欄位的系列資料。
2. 觀察系統回饋。

**預期結果**

1. 系統將該播放清單視為無效。
2. 系統提供明確錯誤訊息。
3. 系統不自行補值、不掃描資料夾、不自動生成播放清單。

### Edge-PL-003 清單順序與資料夾命名衝突

**目的**

驗證系統以 `playlist.json` 順序為準，而不是依資料夾名稱字典序排序。

**步驟**

1. 準備一份 `playlist.json`，其 `episodes` 順序與 `ep01/`、`ep02/`、`ep03/` 的字面順序不同。
2. 輸入對應 CID。

**預期結果**

1. 介面顯示順序仍以 `playlist.json` 為準。
2. 系統不會依 `ep01/`、`ep02/` 等資料夾名稱重新排序。

### Edge-PL-004 系列模式不應過早寫入觀看歷史

**目的**

驗證系列模式下的待播初始化與真正開始播放之間，有明確的歷史紀錄邊界。

**步驟**

1. 清空觀看歷史。
2. 輸入 `CID-SERIES-OK`，停留在預設待播畫面。
3. 檢查觀看歷史。
4. 再由使用者主動按下播放。
5. 再次檢查觀看歷史。

**預期結果**

1. 只停留在待播畫面時，不產生新的觀看歷史。
2. 使用者主動開始播放後，才可寫入對應的觀看歷史。
3. 歷史紀錄可區分系列根 CID 與實際播放集數。

# 播放器需求規格書 (SRS)

## 1. 文件目的

本文件定義 IPFS HLS 播放器在播放互動層與播放器下方影片資訊區的使用者需求，作為實作、測試與後續維護的依據。

目前版本除鍵盤快捷鍵外，也新增 sidecar metadata 版面需求，讓播放器能以 `info.json`、`cover.webp`、`avatar.jpg` 驅動標題、上傳者資訊與說明區。

## 2. 適用範圍

本規格適用於前端播放器介面，範圍包含：

- `VideoPlayer` 元件的鍵盤互動行為
- 播放器下方的影片標題列
- 上傳者資訊與右對齊互動按鈕列
- `info.json`、`cover.webp`、`avatar.jpg` 的 sidecar 資料載入規則
- 影片播放時間的 seek 規則
- 播放與暫停切換規則
- 與表單輸入、可編輯控制項的衝突避免

本規格不涵蓋：

- 音量快捷鍵
- 全螢幕快捷鍵

## 3. 功能需求

### FR-UI-1 Sidecar 資產同層讀取

當使用者載入某個影片 CID 時，播放器必須從與 `index.m3u8` 同層的目錄讀取 sidecar 資產：

- `cover.webp` 作為播放器封面
- `info.json` 作為影片 metadata
- `avatar.jpg` 作為上傳者頭像

若 `avatar.jpg` 或 `info.json` 缺失或載入失敗，介面必須退回預設顯示，不得出現破圖或阻斷播放。

### FR-UI-2 標題位置

播放器下方第一個資訊區塊必須顯示影片標題，且標題內容優先來自 `info.json.title`。

- 不得在該位置顯示泛用播放狀態訊息，例如 `資源就緒`、`請手動播放`
- 若 metadata 尚未就緒，可暫時不顯示標題或使用預設標題

### FR-UI-3 上傳者與互動按鈕列布局

在標題下方，介面必須呈現一整列內容：

- 左側：上傳者頭像、名稱、頻道／分類輔助資訊與 Follow 按鈕
- 右側：按讚、倒讚、分享、下載等互動按鈕
- 右側按鈕列必須靠右對齊

此列不得被包在說明／metadata 的玻璃框內，需作為獨立資訊列存在。

### FR-UI-4 說明與 metadata 卡片

上傳者資訊列下方必須保留獨立的說明卡片，用於顯示：

- 影片摘要統計資訊
- `info.json.description`
- metadata grid，例如 `id`、`channel_id`、`upload_date`、`duration_string`、`resolution`、`fps`、`categories`
- tags 列表

### FR-UI-5 metadata 驅動標題同步

`VideoInfo` 在成功讀取 `info.json` 後，必須能將標題同步回傳給上層容器，以更新播放器下方標題列。

### FR-KEY-1 左右鍵 seek

當播放器已初始化且頁面接收到鍵盤事件時：

- 按下 `ArrowLeft` 必須將播放時間倒退 `5` 秒。
- 按下 `ArrowRight` 必須將播放時間前進 `5` 秒。

### FR-KEY-2 空白鍵播放控制

當播放器已初始化且頁面接收到鍵盤事件時：

- 按下空白鍵必須在播放與暫停之間切換。
- 若播放器目前為暫停狀態，按下空白鍵後必須開始播放。
- 若播放器目前為播放狀態，按下空白鍵後必須暫停播放。

### FR-KEY-3 seek 邊界限制

播放器處理快捷鍵 seek 時，目標播放時間必須限制在合法範圍：

- 不得小於 `0`
- 若媒體總長度可取得，不得大於影片總長度

### FR-KEY-4 表單與互動控制保護

當焦點位於以下元素或其互動子樹時，播放器不得攔截左右鍵 seek 或空白鍵播放控制：

- `input`
- `textarea`
- `select`
- `button`
- `a[href]`
- `contenteditable` 區域
- 其他具備 `button`、`slider`、`menuitem`、`textbox` 等互動角色的元素

### FR-KEY-5 修飾鍵保護

當鍵盤事件符合任一條件時，播放器不得處理播放快捷鍵：

- 事件已被其他邏輯 `preventDefault`
- 使用者同時按住 `Ctrl`
- 使用者同時按住 `Alt`
- 使用者同時按住 `Meta`

## 4. 驗收準則

- 載入某個 CID 時，播放器應向同層路徑請求 `cover.webp`、`info.json` 與 `avatar.jpg`。
- 播放器下方第一行應顯示影片標題，而非播放狀態訊息。
- 標題下方應顯示上傳者資訊；互動按鈕列需位於同一橫列的右側並靠右對齊。
- 說明、metadata 與 tags 應出現在下一個獨立卡片中，而不是與上傳者資訊共用同一框。
- 當 `avatar.jpg` 載入失敗時，介面應退回預設頭像，不得顯示破圖。
- 當目前播放時間為 `10` 秒且焦點不在互動控制項內，按下 `ArrowRight` 後播放時間應變為 `15` 秒。
- 當目前播放時間為 `3` 秒且焦點不在互動控制項內，按下 `ArrowLeft` 後播放時間應變為 `0` 秒。
- 當播放器為暫停狀態且焦點不在互動控制項內，按下空白鍵後播放器應開始播放。
- 當播放器為播放狀態且焦點不在互動控制項內，按下空白鍵後播放器應暫停播放。
- 當焦點在搜尋輸入框或其他可編輯區域時，按下左右鍵不得改變播放器時間。
- 當焦點在搜尋輸入框或其他可編輯區域時，按下空白鍵不得切換播放狀態。
- 當事件已被 `preventDefault` 或帶有修飾鍵時，播放器不得消耗該事件。

## 5. 對應測試

此需求至少應由單元測試覆蓋：

- `info.json` 的欄位正規化與讀取失敗 fallback
- 播放器下方標題列與 `VideoInfo` 的版面順序契約
- 上傳者資訊列在左、互動按鈕列在右且靠右對齊的版面契約
- 空白鍵播放 / 暫停切換
- 左右鍵對應 `±5` 秒 seek
- seek 邊界 clamp 行為
- 互動元素與輸入框忽略規則
- 修飾鍵 / 已攔截事件的忽略規則

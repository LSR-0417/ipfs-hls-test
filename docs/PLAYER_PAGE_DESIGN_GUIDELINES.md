# 播放器頁面設計準則

## 1. 文件目的

本文件定義播放器頁面的 page-level 版面原則，作為畫面調整、元件整併與視覺一致性檢查的依據。

本文件聚焦於：

- 頁面主要內容區塊的分隔方式
- 同層主要區塊之間的對齊關係
- 區塊內部內容的起始位置與寬度原則
- 容器責任的劃分方式

本文件不描述具體功能流程，也不描述特定元件的實作方式。

## 3. 適用範圍

本規範適用於播放器頁面中，同一層級、彼此並列或堆疊的主要內容區塊，例如：

- 主播放區
- 輔助資訊區
- 推薦內容區

判斷原則如下：

- 該區塊直接承接 page-level 內容排列
- 該區塊是視覺分區的主要邊界
- 該區塊的顯示或隱藏會影響整段內容，而非單一小元件

## 4. 主要區塊盒模型契約

播放器頁面的主要內容區塊，應共享一致的 page-level 盒模型與分隔邏輯。

其中，具體的容器 spacing、起始線與內容貼齊規則，已獨立整理到：

- [CONTAINER_DESIGN_GUIDELINES.md](./CONTAINER_DESIGN_GUIDELINES.md)

本文件只保留播放器頁面的高階設計原則，不重複記錄容器層級的具體數值。

## 5. 對齊原則

同層主要內容區塊必須遵守下列對齊原則：

- 左側起始線一致
- 上方起始線一致
- 內容流向以區塊上邊界為起點
- 不允許單一區塊額外向內縮排，破壞整體節奏

這代表在視覺上，所有 page-level 區塊都應該被視為同一組版面系統中的兄弟節點，而不是各自獨立定義起始位置。

## 6. 區塊內部內容原則

主要區塊內部的內容應維持一致的排列邏輯：

- 內容必須遵守同一組起始線
- 內容必須維持清楚的垂直閱讀順序
- 區塊內部不應自行破壞 page-level 的對齊節奏

具體的容器貼齊與 spacing 契約，應以容器設計準則為準。

## 7. 容器責任歸屬

頁面留白的責任應明確分層：

- page-level 區塊：負責主要區塊之間的分隔與外圍留白
- 區塊內部元件：負責自身內容排列，但不應重新定義 page-level 的起始線

若同一份留白同時由父層與子層重複定義，容易造成：

- 起始線不一致
- 實際間距難以預測
- 後續調整時必須同時修改多個層級

因此，page-level spacing 應集中管理，不應分散在多個子元件中；具體 spacing 契約應統一收斂在容器設計準則中。

## 8. 容器精簡原則

應保留的容器：

- 代表一個獨立的頁面區塊
- 是視覺分區或顯示切換的邊界
- 有明確的版面責任

應移除的容器：

- 只用來再包一層，沒有新增語意、狀態或版面責任
- spacing 可以直接由父層或實際內容節點承接
- 拿掉後不影響畫面意義、功能切分與維護理解

## 9. 不建議的模式

以下模式應視為反模式：

- 父區塊已提供 page-level 留白，子區塊再重複加入同類型留白
- 為了拉出間距而新增沒有語意與責任的包裝層
- 同層區塊採用不同的左側基準線
- 內容不是從區塊頂部開始，而是各自再往下偏移

這些模式會直接降低版面一致性，並提高維護成本。

## 10. 調整前檢查項目

在修改本規範或套用到新頁面前，應先確認：

- 這次調整影響的是 page-level 區塊，而不是單一元件內部樣式
- 修改後，同層區塊的左側與上方基準線仍然一致
- 內容是否仍然維持「由上而下、滿寬起始」的排列方式
- 是否引入了新的冗餘 wrapper
- 是否把 page-level spacing 錯放到子元件內部

若上述條件無法成立，應重新界定責任層級，而不是直接修改 spacing 數值。
